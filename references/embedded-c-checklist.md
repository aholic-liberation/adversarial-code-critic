# 通用嵌入式 C 批判清单

critic 每轮对照本清单逐条排查。每条都给出「典型症状」，帮你落到具体 file:line。本清单只覆盖**芯片无关**的通用问题；芯片专属坑点见 SKILL.md 指路的平台 skill。

## 1. 中断 / ISR
- [ ] 共享变量：ISR 写入、主循环读取（或反之）的变量，有没有 `volatile`？
- [ ] ISR 里有没有阻塞操作（`delay_ms`、`printf` 长串、阻塞等待、浮点除）？这些会拖垮主循环、丢中断。
- [ ] 多字节变量（16/32 位计数器）在 ISR 与主循环间读写，有没有临界区/原子性保护？否则读会撕裂。
- [ ] 中断优先级安排是否合理？低优先级 ISR 会不会被高优先级长时间打断导致数据丢失？
- [ ] 中断标志有没有清？漏清会导致反复进中断。
- [ ] ISR 里改了寄存器/外设状态，主循环有没有同步假设？

## 2. 定时器 / 计数 / 回绕
- [ ] 计数器回绕计算用的是**实际周期**，不是想当然的 0xFFFF / 0xFFFFFFFF？
- [ ] 编码器/脉冲计数的差值有没有处理回绕（跨过最大值跳回 0）？
- [ ] 定时器重载值、预分频和实际频率的换算对不对？单位是 tick 还是 ms/μs？

## 3. PID / 控制环
- [ ] 输出方向（±号）对不对？方向反了会正反馈发散。
- [ ] 积分项有没有抗积分饱和（anti-windup）？输出限幅时积分还在累计吗？
- [ ] 微分项用的是否是误差差分（会放大噪声/阶跃尖峰）？需要滤波吗？
- [ ] 各物理量单位换算（编码器 tick → 速度、灰度值 → 偏差）对不对？
- [ ] 控制周期固定吗？还是被主循环其它任务拖得忽快忽慢？

## 4. 内存 / 变量
- [ ] 数组访问有没有越界风险（传感器个数、缓冲区长度）？
- [ ] 局部大数组会不会爆栈（嵌入式栈小）？该不该 static/全局？
- [ ] 变量有没有在使用前初始化？上电初值不定。
- [ ] 整数运算会不会溢出（尤其乘法、累加、ms→tick 换算）？该不该用更宽类型或显式检查？

## 5. 状态机 / 逻辑
- [ ] 每个状态是否都有明确的出边？有没有死状态（进去就出不来）？
- [ ] 边界条件（0、最大值、最小值、空列表）处理了吗？
- [ ] if/else 有没有漏分支、逻辑运算符优先级写错、`=` 写成 `==`？
- [ ] 除零保护有没有（尤其外部输入做除数）？

## 6. 现实工况
- [ ] 主循环有没有被长延时 / 忙等占满，导致响应迟钝、丢事件？
- [ ] 看门狗有没有使能？喂狗位置对不对（会不会在卡死分支里还继续喂）？
- [ ] 上电初始化顺序对不对（外设先初始化再用）？
- [ ] 传感器读数有没有滤波/去抖？噪声会不会直接进控制环？
- [ ] 电机/执行器有没有死区、限幅？反转瞬间有没有危险？
- [ ] 电源/电池电压波动下，ADC 参考、PWM 占空比假设还成立吗？

## 7. 功能是否真的成立
- [ ] 函数名/注释声称的功能，和代码实际做的**一致**吗？
- [ ] 有没有「看似实现、实则空转」的假功能（结果算了但没人用、状态机搭了但从不切换）？
- [ ] 关键路径有没有被 `#if 0`、死条件、提前 return 悄悄短路？
